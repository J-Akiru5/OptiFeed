# Internationalization (i18n)

PakaonAI ships three locales. The URL prefix is the source of truth: `/en/...`, `/hil/...`, `/tl/...`.

| Code | Language | Messages | Coverage |
| --- | --- | --- | --- |
| `en` | English | `apps/web/messages/en.json` | Complete, the base file |
| `hil` | Hiligaynon | `apps/web/messages/hil.json` | Complete |
| `tl` | Tagalog | `apps/web/messages/tl.json` | Core UI overlay; untranslated keys fall back to English |

## How it works

- `apps/web/i18n/routing.ts` lists the locales and the default (`en`). Adding a code here makes `next-intl` accept the locale, the proxy accept the prefix, and every `[locale]` route render it.
- `apps/web/i18n/request.ts` loads the message file for the active locale. For `tl`, it deep-merges `tl.json` over `en.json`, so a missing Tagalog key resolves to English instead of crashing or showing a raw key. This makes Tagalog incremental: add a key path to `tl.json` and it takes effect immediately.
- `apps/web/components/locale-switcher.tsx` is the global language dropdown (English / Hiligaynon / Tagalog). It keeps the current pathname, swaps only the locale segment, closes on outside click/Escape/scroll, and renders in a portal so it is not clipped by the landing header, footer, or mobile menu.
- The switcher is used in the landing header/footer, the dashboard header, and the legal pages. Because it calls the localized router, the whole `[locale]` tree — pages, server components, client components and server-action redirects — switches together.

## Tagalog coverage (2026-10-29)

Translated in `tl.json`:

- navigation and the operator menu
- common buttons and confirmations
- login and the password/change-password flow
- error and not-found screens
- dashboard common chrome (read-only, loading, pagination, view toggle, charts labels)
- profile settings, notification preferences and the avatar section
- chat/Pakoy chrome and action labels
- PWA/offline chrome
- platform announcements

Falling back to English for now:

- public landing-page body copy (the landing nav is translated)
- legal privacy/terms text (deliberately left as the authoritative English version)
- superadmin console and help-centre deep copy
- deep dashboard/admin page copy that has not been added to `tl.json` yet

To extend coverage, add the same key path to `tl.json`; do not copy or edit `en.json` for a translation. Preserve ICU placeholders exactly (`{count}`, `{from}`, `{to}`, `{total}`, `{time}`, `{message}`, plural blocks).

## Adding another locale

1. Add the code to `locales` in `apps/web/i18n/routing.ts`.
2. Add `apps/web/messages/<code>.json` (full file) or an overlay plus a merge branch in `request.ts`.
3. Add its display name to `LOCALE_LABELS` in `components/locale-switcher.tsx`.
4. Smoke-test `/<code>/login`, `/<code>/dashboard` and the switcher on the landing page.
5. Run the normal `pnpm lint`, `pnpm typecheck`, `pnpm test` and build gates.

## Notes

- The locale prefix is required; `/dashboard` redirects to the default locale.
- `proxy.ts` derives the locale from `routing.locales`; it does not keep a second hardcoded list.
- The document direction is left-to-right for all three locales.
- Release versioning is owned by the release/integration agent. This document does not change `package.json`, `VERSION`, tags or `CHANGELOG.md`.
