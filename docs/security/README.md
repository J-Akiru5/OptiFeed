## CI controls

Two workflows, deliberately separate so one can fail without hiding the other:

| Workflow | Control | Fails when |
| --- | --- | --- |
| `.github/workflows/security.yml` (I-62) | `pnpm audit --prod --audit-level=high` with an expiring allowlist | A critical/high advisory is not allowlisted, or an allowlist entry expires |
| `.github/workflows/sbom.yml` — `sbom` job | CycloneDX SBOM generated by a pinned `syft` binary (checksum-verified, no repository dependency) | The document is not CycloneDX, or fewer than 100 components were cataloged (lockfile not read) |
| `.github/workflows/sbom.yml` — `secret-scan` job | `gitleaks dir` on the working tree, then `gitleaks git` over the last 100 commits (pinned binary, checksum-verified) | Any finding not allowlisted in `.gitleaks.toml` |

Both jobs upload artifacts: the SBOM for 90 days, the gitleaks SARIF for 30 days (written even when
the scan fails).

### Why `syft` and not `@cyclonedx/cyclonedx-npm`

The preferred tool was checked first: `@cyclonedx/cyclonedx-npm` is npm-only — its documented
requirements are `npm >= 9` with a `package-lock.json`/`npm-shrinkwrap.json`, and this is a pnpm
workspace with `pnpm-lock.yaml`. The current `@cdxgen/cdxgen` alternative requires Node 24 and
pnpm 12, while the repository pins Node 22 and `pnpm@10.33.3`. `syft` catalogs `pnpm-lock.yaml`
without installing anything, so it measures the lockfile the app actually ships. See the SBOM job's
comments for the pinning rationale.

### Secret-scan baseline

`.gitleaks.toml` extends the built-in ruleset and allowlists exactly three things, each with a
written reason in the file: a fake key in a test that proves pasted keys are rejected, a retired
demo device token that appears in documentation and a frozen plan, and the allowlist file itself
(it necessarily repeats those values). Nothing else is suppressed; there is no path-wide or
rule-wide exemption.

The full history was scanned during this workstream (609 commits, gitleaks 8.30.1 with the default
rules plus the allowlist): 11 findings, all in historic versions of test fixtures and docs (`error-scrub.test.ts`,
`error-capture.test.ts`, `firmware/README.md`, `docs/firmware-main.ino.md`,
`Firmware-Implementation`). Every value is a placeholder (`not-a-real-signature`,
`0123…cdef`, `sb_secret_abcdefghijklmnopqrstuvwxyz`, the demo token); no live credential was
found, so no rotation was required. The CI gate scans the most recent 100 commits, which are clean.

## Running the scanners locally

```bash
# Secret scan (same config and rules as CI)
gitleaks dir . --config .gitleaks.toml --redact --no-banner --verbose
gitleaks git . --config .gitleaks.toml --log-opts="--max-count=100" --redact --no-banner --verbose

# SBOM (needs syft on PATH; no install step)
syft dir:. -o cyclonedx-json=sbom.cdx.json
```

Windows binaries are published on the gitleaks and syft release pages; the CI workflow shows the
exact versions and the checksum step.
