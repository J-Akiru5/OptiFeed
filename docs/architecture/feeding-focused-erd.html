Farm owner, tenant admin, farmer, superadmin

The farm owner is the User referenced by Farm.ownerId → User.farmId. Tenant permissions come from Membership.role (OWNER, ADMIN, OPERATOR, VIEWER), not from a special “Super Admin” value in User.role. Platform superadmins are separate PlatformAdmin grants. Organization/member IDs are logical links in this Prisma schema; it does not declare those FK relations.

The feeding path

A pond holds the plan. A schedule edit becomes a ScheduleCommand referencing both pond and device. A manual request becomes a FeedRequest; a physical button can dispense without one. FeedEvent is the event record for what the device reports, not a target/actual “feeding event” table.

Legacy and scope notes

The old Device / FeedingEvent pair still exists but is deprecated and excluded from the active flow. “Feed config” and “telemetry reading” are not standalone tables: config is split among pond/device/command records; current sensor values are on EnergyDevice, with separate history logs.

Schema basis: apps/web/prisma/schema.prisma at origin/main, inspected 2026-11-19. Simplified for feeding; not a migration or a proposed schema change.
