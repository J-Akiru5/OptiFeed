Executive Summary

Every state-changing user action on the dashboard and every device-reported event is now recorded in the deviceStateEvent table and visible on /dashboard/audit. Thirteen event types from seven "silent" actions were added; five display-only event types that previously had producers were connected. All changes pass pnpm lint, pnpm typecheck, and pnpm build.

Decision Scope: Option B (Moderate)

Jeff approved "Option B — Moderate" from the options memo. Scope includes all user-initiated write actions, device connectivity transitions, command lifecycle events, and the five previously-unconnected display-only event types. Notification actions were excluded (read-heavy, no operational value). Login/logout deferred until real auth ships.

Chosen scope: 13 event types across 4 action files, 2 API routes, 1 page, and 2 message files.

Previously Silent Actions (Now Logged)

Seven server actions that previously wrote no audit event at all now produce a deviceStateEvent.create call following the same pattern as updateScheduleCommand():

1. toggleDevicePause → pause_toggled Added
File
lib/actions/schedule.ts:12
Metadata
{ isPaused }
After — pause_toggled event
await prisma.energyDevice.update({
  where: { id: deviceId },
  data: { isPaused },
});

await prisma.deviceStateEvent.create({
  data: {
    deviceId,
    eventType: "pause_toggled",
    source: "user",
    actorId: "demo-farmer-1",
    metadata: { isPaused },
  },
});

5. updatePondSettings → settings_changed + schedule_changed Added
File

When an EnergyDevice is linked, updatePondSettings delegates to updateScheduleCommand (which emits schedule_changed) and then emits its own settings_changed event. The fallback path (no device) has no deviceId to log against and remains silent — this is an edge case.

6. registerEnergyDevice → device_registered Added
File
lib/actions/energy.ts:125
Metadata
{ mac, label }
7. saveBiomassLog → biomass_logged Added
File
lib/actions/biomass.ts:68, 98
Metadata
{ avgWeightKg, sampleCount, gramsAdjusted|gramsProposed }

Two emission points inside the Prisma transaction: one when the auto-adjust is rejected (deviation > 50%), one when it succeeds. Both use tx.deviceStateEvent.create so the event is atomic with the biomass log.

Files Changed

Eight files were touched across the implementation:

  • apps/web/lib/actions/schedule.ts — pause_toggled, manual_trigger, command_failed, schedule_changed
  • apps/web/lib/actions/energy.ts — manual_trigger (requestFeed), hopper_calibrated, device_registered
  • apps/web/lib/actions/settings.ts — settings_changed
  • apps/web/lib/actions/biomass.ts — biomass_logged (accepted + rejected)
  • apps/web/app/api/ingest/route.ts — pellet_low, pellet_refilled, schedule_applied
  • apps/web/app/[locale]/(dashboard)/dashboard/audit/page.tsx — eventTypeConfig + filterGroupToTypes for new event types
  • apps/web/messages/en.json — English translations for 5 new event types
  • apps/web/messages/hil.json — Hiligaynon translations for 5 new event types

The schedule-sync/route.ts and lib/actions/audit.ts were not modified — they already had the correct event producers and query logic.

Architecture

The audit trail flows through three layers. Stars indicate new or modified producers:

User Actions (lib/actions/*.ts) ├── schedule.ts ─ toggleDevicePause ★ pause_toggled ├── schedule.ts ─ triggerManualFeed ★ manual_trigger ├── schedule.ts ─ updateScheduleCommand ◆ schedule_changed ★ command_failed ├── energy.ts ─── requestFeed ★ manual_trigger ├── energy.ts ─── saveHopperCalibration ★ hopper_calibrated ├── energy.ts ─── registerEnergyDevice ★ device_registered ├── settings.ts ─ updatePondSettings ★ settings_changed └── biomass.ts ─ saveBiomassLog ★ biomass_logged Device Events (app/api/ingest/route.ts) ├── heartbeat ────────── connected ◆ connected ├── heartbeat ────────── disconnect detection ◆ disconnected ├── heartbeat ────────── pellet low (≤5%) ★ pellet_low ├── heartbeat ────────── pellet refilled ★ pellet_refilled ├── feed_dispensed ─── device-reported feed ◆ feed_dispensed ├── feed_dispensed ─── orphaned request match ◆ feed_reconciled └── schedule_acked ─ device acks command ◆ command_acked ★ schedule_applied Device Poll (app/api/schedule-sync/route.ts) └── GET ───────────────── dispatch pending command ◆ command_sent Storage → Query → Display └── deviceStateEvent table └── getAuditLog() → audit/page.tsx ◆ = existing ★ = added in this pass
