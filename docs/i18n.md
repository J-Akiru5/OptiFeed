# Internationalization (i18n)

PakaonAI ships three locales. The URL prefix is the source of truth: `/en/...`, `/hil/...`, `/tl/...`.

| Code | Language | Messages | Coverage |
| --- | --- | --- | --- |
| `en` | English | `apps/web/messages/en.json` | Complete, the base file |
| `hil` | Hiligaynon | `apps/web/messages/hil.json` | Complete |
| `tl` | Tagalog | `apps/web/messages/tl.json` | Complete, machine-drafted; review queue in `apps/web/messages/tl.draft-keys.json` |

## How it works

- `apps/web/i18n/routing.ts` lists the locales and the default (`en`). Adding a code here makes `next-intl` accept the locale, the proxy accept the prefix, and every `[locale]` route render it.
- `apps/web/i18n/request.ts` loads the message file for the active locale. For `tl`, it deep-merges `tl.json` over `en.json` with `i18n/merge-messages.ts`, so a key that is missing from Tagalog resolves to English instead of crashing or showing a raw key. The fallback remains a safety net even though the catalogue is complete.
- `apps/web/components/locale-switcher.tsx` is the global language dropdown (English / Hiligaynon / Tagalog (draft)). It keeps the current pathname, swaps only the locale segment, closes on outside click/Escape/scroll, and renders in a portal so it is not clipped by the landing header, footer, or mobile menu.
- The switcher is used in the landing header/footer, the dashboard header, and the legal pages. Because it calls the localized router, the whole `[locale]` tree — pages, server components, client components and server-action redirects — switches together.

## Tagalog catalogue (#327)

`tl.json` carries the same key set, ICU placeholders, ICU plural branches and
rich-text tags as `en.json`; the parity test enforces all four. The catalogue is
**machine-drafted** and awaiting human review:

- `apps/web/messages/tl.draft-keys.json` lists every key that has not been
  human-reviewed, plus the `reviewedBaseline` recorded before the machine pass
  (331) and the generation method. The language menu labels the locale
  **Tagalog (draft)** while that list is non-empty.
- The 331 strings that existed before the 2026-10-31 machine pass are the
  human-reviewed core. The machine pass did not modify them; human-reviewed
  copy always wins.
- To clear a key, review it in `tl.json` and remove it from
  `tl.draft-keys.json`. `reviewedBaseline` is a floor, so the count does not
  need editing. When the list is empty, remove the `(draft)` suffix from
  `LOCALE_LABELS` in `components/locale-switcher.tsx`, from `LOCALE_OPTIONS` in
  `app/[locale]/login/page.tsx`, and the draft section from `docs/i18n.md`.
- Domain terminology and style: `docs/i18n/tagalog-glossary.md`. Change the
  glossary first, then the catalogue, so later passes do not reintroduce a
  variant.
- Dates, numbers, relative times and plurals are formatted by `Intl` with the
  active locale. `tl` canonicalises to CLDR `fil`; `lib/__tests__/tagalog-locale.test.ts`
  checks month/day labels against `Intl.DateTimeFormat("fil")`, number
  grouping, relative time and the `one`/`other` plural categories.

### Review queue boundary

The parity gate treats Tagalog like English and Hiligaynon for **structure**
(key set, placeholders, plural branches, rich-text tags, no blank values). It
does not judge translation quality: that is the human review recorded by
`tl.draft-keys.json`. A key added to `en.json` without a Tagalog translation
fails the parity test; until the translation lands, the runtime overlay serves
the English string rather than a raw key.

## Hiligaynon

The Hiligaynon catalogue is standalone and complete. It is not merged over
English, so a key missing from `hil.json` reaches the reader as a raw dotted
key. The parity test therefore holds it to exact key and placeholder equality.
Keep its behaviour unchanged when touching Tagalog.

## Adding another locale

1. Add the code to `locales` in `apps/web/i18n/routing.ts`.
2. Add `apps/web/messages/<code>.json` (full file) or an overlay plus a merge branch in `request.ts`.
3. Add its display name to `LOCALE_LABELS` in `components/locale-switcher.tsx`.
4. Extend `lib/__tests__/i18n-parity.test.ts` with the locale's structural gate.
5. Smoke-test `/<code>/login`, `/<code>/dashboard` and the switcher on the landing page.
6. Run the normal `pnpm lint`, `pnpm typecheck`, `pnpm test` and build gates.

## Notes

- The locale prefix is required; `/dashboard` redirects to the default locale.
- `proxy.ts` derives the locale from `routing.locales`; it does not keep a second hardcoded list.
- The document direction is left-to-right for all three locales.
- Release versioning is owned by the release/integration agent. This document does not change `package.json`, `VERSION`, tags or `CHANGELOG.md`.
