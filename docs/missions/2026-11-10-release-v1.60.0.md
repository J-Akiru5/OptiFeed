## Issues that remain open — and why they cannot be closed yet

### #711 — RLS is bypassed by the app role

**Status: not closable.** The issue's premise is a database backstop for tenant
isolation, and that backstop is still not active:

- The application still connects as `postgres` with `BYPASSRLS`.
- `optifeed_app` still has no password and cannot authenticate.
- `getActivePond()` and the identity/scope bootstrap remain privileged.
- Notification acknowledgement writes, ingest and platform paths are unconverted.
- The two-tenant proof still needs a staging copy, an app-role password and
  `TENANT_PROOF_CONFIRM=yes`.

The merged slice 2 only adds correct `set_config` plumbing to the dashboard
notifications read. It does not enforce RLS. Closing #711 while these are true
would hide a P1 security gap. The issue closes only when the remaining slices
pass the two-tenant proof and the role switch is verified (or when the owner
explicitly accepts the residual risk in writing).

### #672 — provider backups/PITR unconfirmed

**Status: not closable.** The documentation contradiction is fixed, but the
provider facts are still **Not verified**. These five values are owner-only
(Supabase Dashboard → project `xjjnkikgkraixlfhhvoh` → Database → Backups):

1. Supabase plan name
2. PITR enabled? (yes/no)
3. Backup retention (days)
4. Earliest restorable timestamp
5. Date checked (UTC) and who checked it

Closing #672 before these are recorded would repeat the false "confirmed" claim
the issue exists to remove. Once the values are in
`docs/operations/backup-and-recovery.md` §4.1, the issue can close.
